# 수동 이동 / 펄스 가이드 속도 분리 — 2026-09-09

## 요청과 확인한 문제

수동 이동 속도와 펄스 가이드 속도를 각각 저장하고 이동 상황에 맞춰 적용한다.
첫 GoTo의 SYNC 완료 검증 수정에 이어 진행한 두 번째 변경이다.

기존 코드는 드라이버의 임시 속도 값을 수동 속도 변수에 다시 저장했다.
또 수동 속도로 전환해도 GUIDE_RATE의 로컬 캐시가 그대로면 다음 펄스에서
가이드 속도를 다시 전송하지 않을 수 있었다. 웹 수동 버튼은 별도 INDI 명령을
직접 보내므로 제어 프로세스의 속도 관리와 이동 유지 시간 처리를 우회했다.

번들 드라이버 패치 `scripts/patches/indi-v2.2.3.1-onstepx.patch`를 확인했다.
OnStepX는 GUIDE_RATE를 공통 `:R<n>#` 속도 선택기로 적용하고 `:GX90#`로
실제 가이드 속도를 읽어 확인한다. 동서·남북에 서로 다른 가이드 속도를 요청하면
거부한다. 따라서 이번 설정은 수동 / 가이드 두 종류이며, 가이드 두 축은 같은 값을 쓴다.

## 저장 및 적용

| 설정 | 저장 키 | 기본값 | 적용 시점 |
|---|---|---|---|
| 수동 이동 속도 | `indi_manual_slew_rate` | 5 (8x, Center) | 수동 속도 변경 / 수동 이동 시작 |
| 미세 펄스 가이드 속도 | `indi_pulse_guide_rate` | 0.5x 항성시 속도 | 다음 가이드 펄스 전 |

기존 수동 속도 선택기와 새 펄스 가이드 속도 선택기는 INDI 웹 화면에서 사용한다.
미세 가이드 속도는 0.25x / 0.5x / 1x 중 선택한다. 큰 오차에서는 기존 정책대로
1x를 임시로 사용하며, 저장한 미세 속도를 덮어쓰지 않는다. 키보드·조이스틱·SkySafari의
기존 속도 명령도 같은 수동 설정을 변경한다. 새 설치 기본 설정에도 두 키를 추가했다.

수동 속도는 드라이버의 일시적인 가이드 속도 조회 결과로 덮어쓰지 않는다.
수동 입력 전에 저장된 수동 속도를 다시 적용하고, 이후 펄스로 돌아갈 때는 가이드
속도를 다시 적용한다. 가이드 사이에 수동 속도를 자동으로 썼다가 되돌리는 반복은 없앴다.

GUIDE_RATE 송신 성공이나 변경된 로컬 캐시는 확인 근거로 쓰지 않는다.
요청 뒤 도착한 드라이버 OK 응답에서 두 축의 속도가 요청과 일치해야 펄스를 보낸다.
응답은 비동기로 기다리며 최대 5초다. ALERT / 시간 초과 / 전송 실패이면 펄스를
차단한다. 성공 응답 후에는 여전히 유효한 최근 솔빙으로 진행하고, 속도 응답 대기만으로
그 솔빙을 사용 완료 처리하지 않는다. 실패 후에는 가이드 속도를 다시 저장하거나
재연결하면 적용을 다시 시도할 수 있다.

수동 이동 중 가이드 설정 변경은 저장만 한다. 펄스 중 수동 **속도 설정**만 변경하면
현재 펄스의 예상 실행 구간이 지난 뒤 적용한다. 펄스 중 실제 **수동 이동** 입력이 오면
정지 요청 → 수동 속도 적용 → 방향 명령 순서로 처리한다. 정지 또는 속도 명령의
전송 실패 시 방향 명령을 보내지 않는다. 웹 시작·유지·정지는 모두 마운트 제어 큐로
전달하며, 기존 1.2초 이동 유지 시간은 제어 프로세스가 관리한다.

정지 요청의 전송 성공은 물리적인 완전 정지 확인과 다르다. 펄스 실행 구간도
전송 후 요청 길이 + 0.5초로 추정한다. 실제 정지·전환 반응은 연결 후 확인해야 한다.
수동 조작 후 자동 추적 재중심 정책은 기존 GoTo/Guide 서비스 정책을 따른다.
전처리 간격, 솔빙 알고리즘, 펄스 공격성 및 펄스 길이 상한은 변경하지 않았다.

마운트는 계속 `usb_absent` 상태여서 물리적인 이동 명령은 시험하지 않았다.

2. 짧게 수동 이동한 뒤 손을 떼어 정지되는지 확인한다.
3. 자동 미세 보정 후 같은 수동 이동을 반복해 수동 속도가 낮아지지 않는지 확인한다.
4. 다시 가이드로 돌아가면 GUIDE_RATE 확인 뒤 펄스가 시작되는지 로그를 확인한다.

## 푸시 화면 속도 표시 추가

푸시/GoTo 화면의 기존 하단 상태 줄에 작은 글씨로 속도를 추가했다.
표시 예: `보정중 S1.2s M5 G0.5>1`.

- `S1.2s`: 솔빙 시도 간격. 기존 간격 계산을 유지한다.
- `M5`: 저장한 수동 이동 속도 단계.
- `G0.5`: 저장한 미세 가이드 배율. 임시 가속 적용을 확인하면 `G0.5>1`로 표시한다.
- `G0.5>1?`: 1배 속도를 요청했으며 드라이버 적용 응답을 기다리는 중이다.
- `M-- G--`: 유효한 최신 마운트 상태가 없다.

가이드의 적용/요청 배율을 상태 파일에 추가했으며 표시만 변경한다.
