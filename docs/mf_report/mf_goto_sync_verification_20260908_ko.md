# 첫 GoTo의 정렬 완료 검증 — 2026-09-08

## 문제와 확인 범위

사용자는 전원 투입 후 첫 GoTo가 다른 방향으로 이동하지만 정지 후 다시 실행하면
정상 방향으로 이동한다고 보고했다. 정렬 완료를 확인한 뒤 이동하도록 요청했다.
2번 수정 사항은 사용자가 추후 설명하기로 했다.

기존 PiFinder GoTo와 추적 복구 GoTo는 SYNC와 GoTo를 별도 명령으로 연속 전송했다.
SYNC 함수의 성공 반환은 INDI 전송 요청 성공을 의미하며 드라이버의 정렬 완료를
확인하지 않았다. 또한 PyIndi 송신 함수는 로컬 속성 값을 먼저 바꾸므로 그 캐시를
다시 읽는 것만으로는 정렬 완료를 검증할 수 없었다.

이 누락은 코드에서 확인했다. 첫 이동 방향 오류의 실제 원인이 이것 하나인지까지는
확정하지 않았다. 적용 전 장비 상태는 `usb_absent`, 이동 없음, 추적 대상 없음이었다.

## 변경 동작

PiFinder GoTo와 추적 복구 GoTo는 요청 ID가 있는 `sync_and_goto` 한 건으로 처리한다.

1. SYNC 모드를 요청하고, 이후 수신한 ON_COORD_SET의 OK / SYNC 응답을 확인한다.
2. 정렬 좌표를 전송하고, 이후 수신한 EQUATORIAL_EOD_COORD의 OK 응답을 확인한다.
   응답 좌표와 요청 좌표의 구면 각거리 차이는 0.5분각(30초각) 이하여야 한다.
3. 추적 활성화를 요청하고 SLEW 모드의 새로운 OK 응답을 확인한다.
4. 위 검증을 마친 후에만 목표 좌표를 보내 GoTo를 실행한다.

30초각은 마운트 좌표 응답의 일치 허용치다. 카메라 솔빙 정확도나 접안부 중심 정밀도를
30초각으로 보장한다는 의미가 아니다. 정상 응답을 받으면 즉시 다음 단계로 진행하며,
각 검증 단계의 제한 시간은 5초다. 상위 서비스는 해당 요청의 결과를 최대 25초 기다린다.
GoTo 도착 판정의 시간 기준도 정렬 대기 시작이 아닌 실제 이동 명령 시점으로 맞췄다.

드라이버 거부, 시간 초과, 연결 변경, 송신 예외 또는 대기 중 정지·수동 이동이 발생하면
보류 중인 GoTo를 취소한다. 늦게 도착한 응답으로 취소한 GoTo가 재개되지 않는다.
상위 서비스가 정렬 실패를 확인하면 자동 복구 재시도도 중단한다.
다른 장치, 이전 연결 세대, 이전 요청의 완료 상태는 검증 근거로 사용하지 않는다.

첫 PiFinder GoTo의 기준 좌표에는 최근 12초 이내의 유효한 고품질 카메라 솔빙을 요구한다.
이미 조건에 맞는 솔빙이 있으면 다음 솔빙을 새로 기다릴 필요가 없다.
전처리 실행 간격은 변경하지 않았다.

이번 변경은 일반 PiFinder GoTo와 그 추적 복구 경로에 적용한다. 별도 단독 SYNC,
마운트 자체 GoTo, 다점 정렬 및 백래시 측정 전체를 이 절차로 변경한 것은 아니다.
실행 중 펄스와 수동 이동의 전반적인 우선순위 처리는 별도 수정 범위로 남긴다.

  정지·수동 입력, 정렬 완료 후 이동 모드 대기 중 정지 시 이동 차단을 검증했다.

테스트는 실제 마운트 구동이나 전원 투입 직후의 펌웨어 동작을 검증한 결과가 아니다.

23:50:50 KST에 PiFinder 서비스를 재시작해 적용했다. 새 PID 18054의 서비스가
active이며 GoTo 서비스와 마운트 상태 파일의 갱신을 확인했다. 사용자 설정 파일은
적용 전후 바이트 단위로 동일하다. 마운트는 계속 `usb_absent` 상태여서 실제 이동은
실행하지 않았다. 적용 상세는 `deployment.json`, 소스는 `source_after/`에 저장했다.
