# SkySafari 정렬 응답 지연: 직전 솔빙으로 즉시 계산

## 확인한 현상

2026-09-06 22:45:09.840(KST)에 SkySafari가 TCP 4030으로 `:CM#`를 보냈다.
3.018초 후 클라이언트가 FIN을 보냈고, PiFinder의 `Coordinates matched.#` 응답은
3.453초 뒤에야 전송됐다. PiFinder 로그에서는 target pixel 저장과 INDI sync
전달이 완료됐다. 사용자에게는 SkySafari의 “명령어 실패”가 표시됐다.
22:44:01의 별도 요청은 2.524초 뒤 응답했으므로, 모든 요청이 같은 지연은 아니다.
패킷 기록은 `/tmp/pifinder_sync_followup_capture.jsonl`에 보존했다.

기존 구현은 `AlignOnRaDec`를 솔버에 넣고 새 솔빙을 최대 15초 기다렸다.
SkySafari 클라이언트 대기보다 길어, 실제 정렬이 적용됐어도 앱은 실패를 표시할 수 있었다.

## 수정

SkySafari 정렬은 새 솔빙을 요청하지 않는다. 품질·연속성 검증을 통과해 게시된
직전 솔빙의 카메라 RA/Dec/Roll, 실제 FOV, 회전된 영상 크기 및 512 좌표 매핑
정보를 사용해 대상의 target pixel을 계산한다. 계산과 설정 저장 후 성공 응답을 보낸다.
카메라 축 좌표와 tetra3의 pinhole 투영을 사용하며, 얼라인된 축 좌표를 다시
카메라 중심으로 간주하지 않는다. Cedar/SEP의 중앙 부분집합도 실제 전체 캔버스
크기를 보존한다. 타일 등 명시적 캔버스 정보가 없는 결과는 추정해서 재사용하지 않는다.

재사용 조건은 다음과 같다.

- 솔빙 프레임이 5초 이내이며, 보관된 측정 시각과 마지막 성공 시각이 일치한다.
- IMU가 신선하고 유효하며, 이동 중이 아니고 솔빙 당시 자세와 0.05도 이내이다.
- 마운트가 이동 중이 아니다.
- 카메라, 렌즈, 수동 초점거리, 화면 회전, 활성 광학 보정 ID가 일치한다.
- 대상이 솔빙된 영상 안에 있고 모든 기하 값이 유효하다.

실패한 솔빙 시도가 발생해도 직전 성공 투영의 원래 시각을 보존한다. 위 조건을
만족하지 못하면 `Alignment unavailable.#`를 즉시 반환하고, 지연된 정렬 명령이나
부분적인 INDI sync/추적 대상 설정을 남기지 않는다. LCD의 새 프레임 정렬,
INDI 전용 모드, 첫 솔빙 전 IMU 정렬 및 다점 정렬 경로는 기존 동작을 유지한다.
솔버 전처리와 비동기 작업 전달 간격은 변경하지 않았다.

## 검증

tetra3의 실제 픽셀→벡터 변환과 임의 회전 행렬로 역검증했다. 512 프레임,
회전된 직사각형 전체 프레임, 980 정사각형 프레임에서 기존 매핑과 일치했다.
RA 경계, quaternion 부호, 시간 경과, 움직인 뒤 정지, 광학 변경, 시야 밖 대상,
실패 시도 뒤 원래 측정 시각 보존, 응답 큐를 기다리지 않음 및 부분 sync 방지를 검증했다.
관련 테스트 223개, 추가 솔빙 정책/광학/보정 테스트 30개가 통과했다.
수정 파일 Ruff, 기존 설정에 따른 MyPy 및 변경분 공백 검사도 통과했다.

CM 처리·전송 시간과 재사용한 솔빙의 나이를 INFO 로그에 남겨 실제 클라이언트
재시험에서 응답 시간과 성공 표시를 함께 확인할 수 있다.
